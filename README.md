# 轮缘磨耗对谱台（Flange Wear Alignment Bench）

把同一轮位的**多期轮缘/踏面二维轮廓**与**版本化标准廓形**做刚体对齐，计算**法向磨耗厚度**并与**标准限界**求交集，解释超限区域。面向轮对测量仪导出的点序：每次采集的原点、旋转、截取范围都可能变化，且一批采集可能**共享同一测头偏差**。

技术栈：TypeScript · Node.js（内置 `node:sqlite`，无原生编译依赖）· 浏览器 Canvas · esbuild · Vitest。

## 安装

```bash
corepack pnpm install --frozen-lockfile
```

## 数据口径（务必先读）

- **坐标系**：`x` 沿车轴方向（轮缘 → 踏面外侧为正），`y` 为径向（背离轮心为正），单位 mm。
- **标准廓形**：`TB-STD-2024.1`，由控制点折线离散后**按实际弧长等距（0.5mm）重采样**，附带每点区段标签、单位切向与指向材料外侧的单位法向、以及“轮缘根部锦标”锚点（根弧底）。
- **标准限界**：`TB-LIMIT-2024.1`，按区段给出法向磨耗报警阈值。**标准版本与限界版本都进入结果指纹与 runId**。
- **法向磨耗厚度**：标准法向指向材料外侧；材料损失使测量点内移，`signedNormal<0`，故
  `磨耗厚度 = -signedNormal − 选定测头偏差(外偏为正)`。
- **区段**：轮缘内侧 `rim_inner`、喉面 `flange_face`、根弧 `flange_root`、踏面 `tread`、外倒角 `outer_chamfer`。

### 固定 fixture（`src/data/fixture.ts`，种子确定）

- 轮位 `1L`，三期：**T0 正向全段**（轻磨耗）、**T1 反向全段**（采集转向相反）、**T2 正向但被截短**（两端缺失、磨耗最重）。
- 三期各自带**不同的随机原点/旋转**；导入顺序被故意打乱（T2,T0,T1），用于证明结论不由导入顺序决定。
- 三期共享同一测头法向偏差（真值 `SHARED_PROBE_BIAS`），并各注入孤立污点。
- 测量廓形在紧邻真根底处带一个“孪生根凹”，使根部锦标检测产生两个显著性接近的局部对齐；三期各自保留**两个近似同分候选**，二者都可追溯（内容哈希 ID、种子来源、变换参数）。

## 关键算法约束（对应验收点）

1. **点序按实际弧长重建**：以累积弦长为弧长，等距线性插值重采样；不按 x/y 坐标排序。
2. **转向相反必须语义翻转**：用“开放折线弦闭合的有符号面积（Shoelace）+ 质心有向弦侧一致性”判定方向——旋转/平移不变、点序反向严格变号；判为 `reverse` 时对数组执行 `reverse()` 显式翻转，**绝不坐标排序**。判定方法、证据与置信度写入结果。
3. **截短段不端点填充**：只有垂足严格落在标准折线边内部（`interior`）的测量点才参与配准/磨耗；标准弧长覆盖之外保持 `null`，不用端点平移或钳制填满。
4. **多局部近似同分全保留**：point-to-plane ICP（切向自由滑动）做多候选搜索；相对最优分差距 ≤ 阈值（默认 0.30）的候选全部保留。代表性候选在近似同分集合中按**内容指纹**确定性选取，**不用导入顺序决定**。
5. **锁定轮缘根部锦标**：以根弧底为软锚点参与最小二乘（而非硬钉扎），在保持整体配准质量的同时产生“真根/孪生根”两个高质量、分数接近的假设。
6. **限界版本进入指纹**：runId 与每轮廓指纹均含 `standardVersion`、`limitVersion`、基准段、锁根/污点开关、阈值、候选内容与测头选择。

## 页面操作

- 勾选**基准段**、**锁定轮缘根部锦标**、**排除污点**，调整近似同分阈值后自动重算。
- 每张期卡片并排显示：标准廓形（按区段着色）+ 对齐后测量点 + 根弧锦标 + 超限点 + 污点，下方为法向磨耗厚度曲线与 0 线。
- 卡片内可：在多个对齐候选间切换（近似同分高亮）；对**该条轮廓独立**设置测头偏差（置零 / 采用整批共享值 / 自定义）。
- 顶部可把**共享测头偏差候选一键应用到整批**；即便整批应用，每条轮廓的独立覆盖仍然生效。
- 顶部显示每个超限交集区的人类可读解释（区段、弧长区间、峰值、阈值、限界版本）。
- “重放复核”用库中原始输入与参数重新计算并比对指纹；“导出运行记录”写出 JSON 到 `exports/`；“清空数据库”后可重新导入，runId/指纹保持一致。

## SQLite（`data/bench.sqlite`）

表：`runs`（运行与参数/指纹）、`profiles`（每轮廓结果、方向、原始点云、独立选择）、`candidates`（每候选变换/分数/种子）。清空：

```bash
corepack pnpm reset
```

清空后在页面点“重新导入并分析”（或 `POST /api/analyze`）即可复核，指纹与清空前一致。

## HTTP API

- `GET /api/health`、`GET /api/standard`
- `POST /api/analyze`（body：基准段/锁根/污点/阈值/整批偏差/逐轮廓覆盖）
- `GET /api/runs`、`GET /api/runs/:id`
- `POST /api/runs/:id/replay`、`POST /api/runs/:id/export`
- `DELETE /api/runs/:id`、`DELETE /api/runs`（清空）
